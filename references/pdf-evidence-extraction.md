# 取证手册：如何从 PDF 里拿到"可以引用的证据"

这份手册解决一个核心问题：**同一张图，目测读出来的数字经常是错的，而报告中又必须给出数字。** 下面是从 PDF 矢量图层反算精确读数的完整方法，以及必须避开的坑。全部结论都在真实文献（Gelman《Bayesian Data Analysis》3rd ed.）上验证过。

## 0. 运行环境（本机实测）

- 需要一个装了 **pymupdf** 的 Python 即可（推荐隔离 venv）。**不要写死别人的绝对路径**——先探测 `python`/`python3` 在哪，再决定用哪个解释器。
- 待装：Windows `<venv>\Scripts\python.exe -m pip install pymupdf`；macOS/Linux `python3 -m pip install pymupdf`。
- 若 `import pymupdf` 失败，退一步试 `import fitz`（旧版 PyMuPDF），两个名字都写在本技能的脚本里了。
- （本机示例，仅作参考：`~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`——换机器时不要照抄这个路径。）
- **执行外部命令（python / pandoc / xelatex）走 Bash 通道**（2026-09-16 实测：coreutils 齐全，stdout 能被工具直接捕获）。**不要交给 PowerShell 工具**——实测它返回退出码 0 却没有启动进程，命令没有任何产物：
  ```bash
  "<venv>/Scripts/python.exe" script.py
  ```
  若确实要用 PowerShell，注意它的 `*>` 重定向出来是 UTF-16，读取前先转码。

### 写盘与编码规范（本机真实踩过的坑）

| 禁止 | 原因 | 正确做法 |
|---|---|---|
| 用 PowerShell 管道/`Set-Content`/`Out-File`（未显式 UTF-8）写入含中文的内容 | 会产生乱码（`????`），中文文件名也会被破坏 | 用 Write 工具整文件写；或 Python 写盘 |
| 在已出现 `????` 的文件上继续做局部替换式修补 | 越补越烂 | **一次性 UTF-8 整文件重写** |
| 不检查就把命令输出当结果用 | 本机 stdout 不被工具捕获 | 重定向到文件后 Read |

**写完必做一次编码自检**（写完中文文件后立刻做）：

```python
b = open(path, "rb").read(160)
assert not b.startswith(b"# ?"), "标题行已损坏"
print("utf8 ok", b[:24])
```

判定：标题行出现 `# ????`、或正文大面积 `?`（0x3F）替代中文 → **文件已损坏**，不得继续修补，必须 UTF-8 整文件重写。控制台 `print` 显示乱码但 `open(...,'rb')` 读出的是正常 UTF-8 字节 → 文件没问题，只是终端代码页问题。

**会话收尾**：若本轮写过中文文件，在收尾清单里一句话说明是否已做编码自检（通过 / 已重写修复）。

## 1. 页码对账（第一步，不能跳）

```python
import pymupdf as fitz
doc = fitz.open(pdf)
for pno in (491, 492):
    page = doc[pno - 1]
    words = page.get_text("words")
    # 页眉/页脚的数字通常就是印刷页码
    head = [w[4] for w in words if w[1] < 60]
    foot = [w[4] for w in words if w[3] > page.rect.height - 60]
    print(pno, head, foot)
```
得到偏移后写进报告的"阅读说明"，全篇引用页码都以它为准。

## 2. 正文文字：抽取 + 修正断行

```python
t = page.get_text("text")          # 逐行；连字符断行会是 "metabo-\nlized"
```
**必须手工修正跨行连字符**（`metabo-\nlized` → `metabolized`），否则引用原文时会出现拼写错误。

**立刻检查每页字符数**：`len(page.get_text("text"))`。若某页为 0 或极小，说明它是**扫描页/纯图片页**——文字层不可用，必须改为渲染成图后人工转写，并在待确认项里登记"该页数字为人工转写"。

## 3. 章节地图

在当前页前后各抽 6–8 页正文，用正则找出所有小节标题与页码：

```python
import re
for pno in range(start, end):
    for line in doc[pno-1].get_text("text").split("\n"):
        s = line.strip()
        if re.match(r"^\d+\.\d+", s) or re.match(r"^(Bibliographic|Exercises|References)", s):
            print(pno, pno - offset, repr(s))
```
据此写出「本节从 p.X 到 p.Y」以及"本页引用但实体在后文"的清单。

## 4. 渲染图表高清图

```python
pix = page.get_pixmap(dpi=430, clip=fitz.Rect(x0, y0, x1, y1))   # 坐标单位 pt（1/72 inch）
pix.save(r"...\fig_xx.png")
```
- 整页预览用 `dpi=200` 就够；**交付给用户/放进报告的图用 400+ dpi**。
- 裁剪范围要靠先渲染整页、目测定位后再微调。经验值：A4/Letter 页面 616×792 pt 左右（本样本 504×720 pt）。
- 渲染出的图**必须用 Read 工具打开人工看一下**（Read 支持图片），确认没有裁掉轴标签。

## 5. 矢量坐标反算（本手册的核心）

### 5.1 取元素

```python
for d in page.get_drawings():
    print(d["type"],              # 's' 描边 / 'fs' 填充+描边 / 'f' 填充
          d.get("width"),         # 线宽 —— 用来区分不同统计含义的线！
          d.get("dashes"),
          d["rect"],              # 外接矩形
          [i[0] for i in d["items"]])   # 'l' 直线段 / 'c' 曲线 / 're' 矩形 / 'qu' 四边形
```

### 5.2 用线宽区分语义（R/base plot 的常见约定）

真实案例（后验中位数 + 区间图）：

| 线宽 `width` | 元素 | 含义 |
|---|---|---|
| `fs` 且 rect 边长 < 2pt | 小方块 | 点估计（后验中位数） |
| `≈ 1.000` | 短竖线 | 50% 区间 |
| `≈ 0.127` | 长竖线 | 95% 区间 |

**不同图的约定不同**，必须先用渲染图核对"哪个元素对应什么"，再用线宽过滤统计。曲线通常用更细的线宽（真实案例中 10 条曲线 `width ≈ 0.070`，正好等于曲线条数）。

### 5.3 用刻度定位建立坐标映射

刻度标签**常常不在文本层**（可能是嵌入图像或字形无 unicode 映射）。此时用**刻度短线**定位：

```python
# y 轴刻度：紧贴轴线的短横线
for d in page.get_drawings():
    r = d["rect"]
    if abs(r.height) < 0.5 and 1 < r.width < 4:   # 刻度短线
        print("tick y =", r.y0, " x range", r.x0, r.x1)
```

然后**用人眼从渲染图上读出每个刻度对应的数值**，建立映射：

- 线性轴：`value(y) = (y_bottom - y) / (y_bottom - y_top) * (v_top - v_bottom)`
- 对数轴：`value(y) = v_ref * 10 ** ((y_ref - y) / pt_per_decade)`

### 5.4 交叉验证（关键一步，务必做）

反算出的映射**必须**用第二条独立证据验证。三种可用的验证手段：

1. **与原文数字互验**（最有力）。真实案例：某图纵轴映射有两种可能（差 1 个 decade），用正文给出的"总体 95% 区间 [15%, 58%]"去检验——只有一种映射能让图上读出的 10 个值落进该区间，另一种会导致全部值远低于区间上界，明显不合理。
2. **与绘图软件的默认轴规则核对**。R 的 `xaxs="r"`（默认）会把数据范围两边各扩 4%（在对数轴上就是对数尺度扩 4%）。真实案例：把曲线全部顶点的 min/max 代入算出的理论绘图框为 y∈[0.4536, 74.22]、x∈[0.000631, 158.6]，与矢量实测的框边界完全一致——**这基本是决定性证据**。
3. **结构自洽**。对数轴的 1-2-5 标注（只标 0.5 / 5 / 50 之类）、线性轴"隔一条标一条"、刻度等距等。真实案例中 y 轴 7 条刻度间距完全相等（15.63 pt）且只标了 3 个值，正好符合"每 0.02 一格、隔一格标注"的规则。

**只有通过验证的映射才能用于写数字。**

### 5.5 反算读数

```python
def v_of(y): return (y0v - y) / (y0v - y1v) * 0.12      # 线性
def pct(y):  return 0.5 * 10 ** ((179.63 - y) / 52.53)  # 对数
```

对每个元素取其 `rect` 的两端（注意 y 向下增大，`y1` 对应较小值），得到区间上下限。

### 5.6 一个坑：点标记可能是位图

`pymupdf` 的 `page.get_bboxlog()` 里若出现大量 `fill-imgmask`，说明**散点是被渲染成小位图的**，`get_drawings()` 拿不到它们，也就无法逐点计数。

对策：不要声称"我数出图上有 N 个点"。改为**由实验设计推断**并明写推断依据（例："按图注与板布局，应为 16 个标准品孔 + 80 个未知样品孔 = 96 点"）。

## 6. 记录与呈现

- 所有反算结果写进 `<out>/vectors/page_<n>.txt`，并在报告的数值表下方注明：**"由 PDF 矢量坐标反算，原文未印出此数"**。
- 报告中区分三档：原文数字 / 由模型设定推出 / 按图读数（见 SKILL.md）。**不要把反算值写成"书中给出"。**
- 若某项无法反算也无法验证，就老实写"目测约"，并把它登记进第二轮审查的待确认项。

### 回退上限（不要反复硬试）

坐标映射**最多尝试 2 次**（换刻度定位方式 / 换映射假设）。两次都不能通过 §5.4 的交叉验证时，立即执行回退：

1. 停手；把该图改用**目测读数**，报告里标 `【按图读数（目测）】`，并在数值表下方注明"未经矢量反算校验"；
2. 把"该图刻度/映射未能确证"写进 `state/oq-ledger.md`（状态 `open`）；
3. **禁止**继续尝试第 3、4 种假设——那只会让报告里留下互相矛盾的读数。

## 7. 先读后引（取证与写作之间的一道闸）

取证素材拿齐之后，写作时仍要守住：**引用任何原句、页码、公式号、读数之前，必须已经实际读到过对应的那一页/那一段。**

- 没读到的**不许引用**，也不许写"书中还提到…"。
- 报告开头写明本次**实际取证范围**（例：`取证范围：PDF 491–492 全文；另回溯 486–498 用于章节地图`）；超出该范围的结论标 `<待确认:…>`，不臆测。
- 完整规则见 `references/anti-hallucination.md`（A–H）。
