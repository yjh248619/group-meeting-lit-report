# group-meeting-lit-report

把学术文献（PDF 图书 / 论文章节）的**指定页码范围**，做成一份能直接用的**组会汇报稿**或**课题组学习稿**。

给一个「PDF 路径 + 页码范围」，它产出英中翻译、内容解析、图表讲解，过两轮审查闸门后交付 Markdown；需要时再导出 LaTeX→PDF 或 Word。

---

## 它解决什么问题

人工做一份文献汇报，痛点基本是这四个：

1. **翻译要逐句对得上**，漏一句就白讲，但没人愿意逐句核
2. **图表要讲清"每个元素代表什么统计量"**，而不只是"这张图显示了……"
3. **最容易出事的是"编"**——凭学科常识补写文献没说的内容，看起来合理，其实无中生有
4. **做完没人复核**，错的地方就一路带进组会

这个技能用两条腿解决：**三档标注**压住幻觉，**两轮审查 + 机器可校验的闸门**压住遗漏。

## 两种输出模式

|  | 组会汇报版（默认） | 课题组学习解析版 |
|---|---|---|
| 交付命名 | **`<起>-<止>-汇报.md`** | **`<起>-<止>-学习.md`** |
| 翻译粒度 | **逐句**（`#### 句 N`，每组从 1 起） | **按段**（`#### 第 N 段`，每页从 1 起） |
| 图表讲解 | 12 条必讲清单：含精确读数表、读图局限、易错点 | 10 条精简清单：元素逐类讲清，不铺开 |
| 公式与概念 | 术语与概念逐条解释 | **前后文联系**：首次定义在哪 / 本页为何用 / 后文还用在哪 / 符号含义与量纲 |
| 附加内容 | 组会预设问答、易错点 | —— |
| 怎么触发 | 「组会汇报」「逐句翻译并讲解」 | 「课题组学习」「学习解析版」「按段翻译」「便于看懂版」 |

文件名固定为「页码-页码-模式」，页码用**书内页**、起止之间用半角连字符。例：书 p.478–479 → `478-479-汇报.md` 与 `478-479-学习.md`（**不加文献简称、不加下划线**）。

两版可以同时产出（会生成两个文件）。**默认走组会汇报版**。

## 核心设计

### 五条铁律（优先级高于效率）

1. **证据回溯** —— 任何关于文献内容的陈述都必须落回证据（原句标页码、图表标图号、公式标公式号）。绝不允许凭学科常识或印象补写文献没说的内容。
2. **阶段闸门** —— 两轮审查未完成、待确认项未全部闭合之前，禁止进入导出阶段。不允许用"用户应该会同意"自行闭合。
3. **不静默降级** —— 工具缺失、编译失败、扫描页没有文字层、图表读不出刻度，必须明说并给替代方案。
4. **交付物落地** —— 必须产出**文件**，不是只在对话里输出。
5. **输出目录先行确认** —— 写任何文件之前先跟用户确认放哪个文件夹；用户没指定就报出建议目录并停下等确认，不默认写当前目录。

### 三档标注（防幻觉的核心机制）

| 标记 | 含义 |
|---|---|
| `【原文 p.N】` | **A 类**：文献原话或原文数字，逐字可回查 |
| `【推论】` | **B 类**：由本文献的模型设定或公式**直接推出**，原文未逐字说明 |
| `【按图读数】` | **C 类**：由图表矢量坐标反算或目测得到，**原文未印出此数** |

规则：**图注说的程度就是结论的上限**。图注说 "generally reasonable"，不得写成"模型充分"。

### 跨页符号与公式：必须交代来源 + 补足推导

目标页范围内**没有给出定义**的字母参数、公式，或由它们推出的数值，必须做两件事：

1. **标注来源**——写清首次定义在哪一页／哪一公式（`首次定义见书 p.474，式 (19.1)`）；图/表读出的标 `【按图读数】` 并写明反算依据；由模型推出的标 `【推论】` 并写明依据；文献通篇未定义的写 `<待确认:…>`。
2. **补足推导**——由公式推出某结果时，写全「依据 → 关键一步（取极限／代入／整理）→ 结果」，**不许只给结论**。

例：从图 19.5 的纵轴读出"零浓度处 ≈ 14.7、平台 ≈ 114"，正确的写法是——

> 式 (19.1)（书 p.474）中当 `x → ∞` 时 `(x/β₃)^(−β₄) → 0`，分式趋于 1，故 `g → β₁ + β₂`，即**平台 = β₁ + β₂，不是 β₂ 单独**【推论】；
> β̂₁、β̂₂ 的数值出处是**书 p.475**【原文 p.475】，平台 `β₁ + β₂ ≈ 14.7 + 99.7 = 114.4`【推论】。

**注意别写反**：`β₂ = 114 − 14.7 ≈ 99.7` 是**因果颠倒**——114 是由 β₁ + β₂ 算出来的，不是从图上读出来的；β₂ 是书 p.475 的后验估计，不是"两个读数相减"。这种"看起来严谨"的错法比不写推导更危险。门禁 **R14** 会就近检查出处标注。

### 机器可校验的闸门

`scripts/check_report.py` 把"审完了没有"变成可执行的判据——**结构类问题阻断**（`exit 1`），内容类问题警告。

| 模式 | 规则 |
|---|---|
| 汇报版（`--mode report`，默认） | R1–R14 |
| 学习版（`--mode study`） | S2 阻断 + S7/S8 警告，共用 R1/R3/R4/R5/R6/R8–R14 |

其中几条值得单独说：

- **R14 符号取值出处** —— 凡「希腊字母参数 ≈/＝ 数值」的断言（如 `β₁ ≈ 14.7`），该行或上下 1 行内必须有来源标记。**默认开启。**
- **R13 输出目录** —— 带 `--outdir "<用户确认的目录>"` 跑，脚本核对报告是否真落在那里。这是把铁律 5 变成机器可查。
- **`--review`** —— 自检记录与待确认项**不放进交付物**（读者要看的是文献，不是工作日志），另存 `_review/` 下的审查记录，门禁从那里读。
- **`--figures-full`** —— 图表按完整清单查（多查「为什么要有这张图」与「这张图还能说明什么」）。
- **`--gate phase2`** —— 进入导出阶段前的硬前置；有待确认项没闭合就阻断。

## 用法

### 你只需要说

> 用 group-meeting-lit-report 解析 `<文献.pdf>` 的书 p.476–477，输出到 `<目录>`

技能会先问清**四项**才开工：文献路径、页码范围、输出模式、输出目录。

### 手动跑（想自己控制时）

**第一步：取证**

```bash
python scripts/extract_pages.py \
    --pdf "<文献.pdf>" --pages 491-492 --book-offset 15 \
    --out work --dpi 430
```

产出 `work/text/`（逐页正文）、`work/pages/`（整页渲染图，用来核对缩进与段落数）、`work/vectors/`（矢量坐标 + 词坐标，用来反算精确读数）。

**第二步：跑门禁**

```bash
python scripts/check_report.py --md <报告>.md --pages 476-477 \
    --outdir "<用户确认的目录>" \
    --review "<用户指定目录>/_review/<起>-<止>-审查记录.md" \
    --figures-full
```

学习版加 `--mode study`。必须以 `[ok] report-gate passed` 或 `[ok] study-gate passed` 与 `exit 0` 结束。

**第三步：导出 PDF**

```bash
python scripts/compile_pdf.py --tex report/478-479-汇报.tex --outdir report/build
```

脚本会调 `latexmk -xelatex` 跑两轮、解析日志、把报错按"出错行 + 常见对策"归类后报给你，而不是甩一整份 `.log`。

## 产出长什么样

```
<用户指定目录>/
├── <起>-<止>-汇报.md                     ← 主交付物（学习版为 <起>-<止>-学习.md）
├── figures/                              ← 高清图，供 PPT 复用
├── evidence/                             ← 取证素材（不对用户交付，但必须留）
│   ├── text/page_<pdf页>.txt
│   ├── pages/page_<pdf页>.png
│   └── vectors/page_<pdf页>.txt
└── _review/
    └── <起>-<止>-审查记录.md              ← 自检与待确认项（不随交付物）
```

导出 PDF / Word 时**沿用同一基名**，于是同一份报告的三份文件同名、只有扩展名不同：

```
<起>-<止>-汇报.tex   →   <起>-<止>-汇报.pdf   →   <起>-<止>-汇报.docx
```

PDF 的名字跟着 `.tex` 主文件名走（`compile_pdf.py` 用主文件基名拼输出路径），所以**只要 `.tex` 起对名，PDF 自动对**；Word 走 pandoc 时保持同一基名即可。**不要把主文件叫 `main.tex`。**

**交付物里不放过程凭据**：自检修订记录与待确认项只写在收尾说明里汇报，不塞进报告正文。

## 已知限制

- **扫描版 PDF**：没有文字层，逐句翻译无法逐字对齐。技能会明确告知并降级处理，不会假装完成。
- **图表精确读数**：依赖 PDF 的矢量层。位图截图里的图无法反算坐标，只能目测并标注 `【按图读数】`。
- **编译环境**：`references/latex-cookbook.md` 里的"已知环境"一节是本机实测记录（TeX Live 2026 + pandoc 3.11），**换机器需要重新探测**。
- **图表清单的机器校验是可选开关**：`--figures-full` 默认不开，需要显式带上，否则 R7 只查四要素。

## 演进记录

每一轮规则改动都追加在 `optimization-record.md`，格式固定：日期说明 / 需求·触因 / 规则摘要 / 验收 / 波及文件。

**历史条目不改**——要推翻旧决定就追加新条目，让读者能看到规则是怎么长成现在这样的。
